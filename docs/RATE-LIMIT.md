# Ограничение частоты запросов к модели

`/api/claude` доступен всем, кто знает адрес приложения, а каждый запрос
стоит денег. Поэтому один адрес не может обращаться чаще 40 раз за 5 минут:
дальше приходит 429 и понятная фраза вместо ответа. Живому читателю этого
хватает с запасом — это восемь сообщений в минуту без единой паузы.

## Почему нужно внешнее хранилище

Счётчик в памяти процесса на serverless почти бесполезен. Замер по проду:
три запроса подряд обслужили три разных инстанса (`x-vercel-id` начинался
на `hgb5z`, `gvfh7`, `7g56x`), и у каждого была своя пустая память. Скрипт,
шлющий запросы в несколько потоков, разошёлся бы по инстансам и не заметил
никакого предела.

Поэтому счёт идёт в Upstash Redis по REST-протоколу — одному хранилищу,
общему для всех инстансов.

## Как подключить (5 минут, бесплатно)

1. В панели Vercel открыть проект → вкладка **Storage** → **Create Database**
   → **Upstash for Redis** (в бесплатном тарифе 10 000 команд в сутки, лимиту
   этого хватает с большим запасом).
2. Связать хранилище с проектом. Vercel сам пропишет в переменные окружения
   `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN`.
3. Передеплоить приложение — код подхватит переменные сам, менять ничего
   не нужно.

Проверить, что заработало: послать больше сорока запросов подряд и увидеть
429. Пока переменных нет, приложение работает штатно, но лимит держится
только в пределах одного инстанса.

## Что делать обязательно, независимо от лимита

Выставить **месячный предел расходов в кабинете OpenAI**
(Settings → Billing → Limits). Ограничитель частоты усложняет злоупотребление,
но абсолютную границу ущерба задаёт только предел на стороне провайдера.

## Если хранилище недоступно

Приложение не отказывает читателям: при ошибке или таймауте обращения к
Redis (2 секунды) счёт молча возвращается к памяти инстанса. Недоступный
Redis не должен превращаться в неработающее приложение.
