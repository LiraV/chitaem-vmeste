# Аккаунты: настройка Supabase

Приложение умеет работать с аккаунтами, но включается это двумя переменными.
Пока они не заданы, вход не показывается и всё работает как раньше — данные
в браузере.

## Шаг 1. Создать проект

1. [supabase.com](https://supabase.com) → зарегистрироваться → **New project**
2. Название любое, регион — ближе к вам, пароль базы придумать и сохранить
3. Дождаться, пока проект поднимется (пара минут)

## Шаг 2. Взять два значения

**Project Settings → API**:

| Что скопировать | Куда |
| --- | --- |
| `Project URL` | `VITE_SUPABASE_URL` |
| `anon` `public` ключ | `VITE_SUPABASE_ANON_KEY` |

Оба значения **публичные** — они попадают в код страницы, и так и задумано.
Доступ к данным ограничивают политики Row Level Security, а не секретность
ключа. Ключ `service_role` не трогайте: он даёт полный доступ в обход политик,
в браузер его класть нельзя.

## Шаг 3. Прописать их в Vercel

```bash
vercel env add VITE_SUPABASE_URL production
vercel env add VITE_SUPABASE_ANON_KEY production
vercel --prod
```

После этого при открытии сайта появится экран входа.

## Шаг 4. Вход через Google (необязательно)

Supabase → **Authentication → Providers → Google** → включить и вписать
Client ID и Secret из Google Cloud Console. Пока не настроено, кнопка «Войти
через Google» будет возвращать ошибку — почта с паролем работает независимо.

## Подтверждение почты

По умолчанию Supabase просит подтвердить адрес письмом. Пока пользователь не
перешёл по ссылке, сессии нет — приложение покажет «Проверьте почту».
Отключается в **Authentication → Sign In / Providers → Confirm email**.
