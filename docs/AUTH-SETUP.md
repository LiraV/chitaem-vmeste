# Аккаунты: вход через Яндекс ID

Пароли остаются у Яндекса — мы их не храним и не видим. Приложение получает
только идентификатор, имя и почту, и выдаёт собственную подписанную сессию.

Пока переменные ниже не заданы, вход не показывается и всё работает как
раньше: данные в браузере.

## Шаг 1. Зарегистрировать приложение

1. [oauth.yandex.ru](https://oauth.yandex.ru) → **Создать приложение**
2. Платформа — **Веб-сервисы**
3. **Redirect URI** — строго этот адрес, иначе Яндекс откажет:
   ```
   https://chitaem-vmeste.vercel.app/api/auth/callback
   ```
4. Доступы в разделе **Яндекс ID API**: адрес почты, имя и фамилия
5. Сохранить — появятся **ClientID** и **Client secret**

## Шаг 2. Прописать в Vercel

```bash
vercel env add YANDEX_CLIENT_ID production       # ClientID
vercel env add YANDEX_CLIENT_SECRET production   # Client secret
vercel env add APP_URL production                # https://chitaem-vmeste.vercel.app
vercel env add SESSION_SECRET production         # см. ниже
vercel --prod
```

`SESSION_SECRET` — длинная случайная строка, которой подписываются сессии.
Сгенерировать:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('base64'))"
```

Не короче 32 символов — сервер откажется работать с коротким. Меняете его —
все текущие сессии перестают действовать, пользователям нужно войти заново.

`APP_URL` должен совпадать с реальным адресом сайта: от него строится
Redirect URI, а он сверяется Яндексом посимвольно.

## Как это устроено

| Эндпоинт | Что делает |
| --- | --- |
| `/api/auth/start` | уводит на страницу согласия Яндекса |
| `/api/auth/callback` | меняет код на токен, заводит сессию |
| `/api/auth/me` | кто сейчас вошёл |
| `/api/auth/logout` | выход |

Обмен кода на токен идёт на сервере, поэтому `Client secret` в браузер не
попадает. Токен Яндекса используется один раз — узнать, кто пришёл, — и не
сохраняется. Дальше работает наша сессия в куке с флагами `HttpOnly`,
`SameSite=Lax` и `Secure`: прочитать её из JavaScript нельзя.

Параметр `state` подписан и продублирован в отдельной куке: подпись доказывает,
что его выпустили мы, кука — что вернулся тот же браузер. Кука одноразовая,
повторный переход по тому же адресу не сработает.
