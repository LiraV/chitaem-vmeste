Формат записи: что делал → что произошло → чего ожидал.

## Найденные баги

### 1. «🗺️ Герои» не строит карту — ИСПРАВЛЕНО В КОДЕ, ждёт выкатки

**Что происходило:** в чате → Инструменты → Герои → «Обновить карту героев» —
вместо списка появлялся ⚠.

**Причина.** Воспроизвёл на живом сайте: запрос возвращает
`OpenAI hit the token limit before producing any text`. GPT-5.5 — модель с
рассуждением, и скрытые токены размышления списываются из того же лимита, что
и видимый ответ. Промпт карты героев содержит три строгих запрета подряд —
не упоминать будущих героев, при сомнении не включать, не выдумывать — модель
добросовестно взвешивает каждого персонажа и расходует весь бюджет на
раздумья. На ответ не остаётся ничего.

Не помогало и увеличение лимита: при 4000 токенах повторялось то же.

**Проверено отдельно:** викторина и обычная переписка работают. Ломалась
только карта героев — у неё промпт тяжелее прочих.

**Что сделано:** провайдер OpenAI теперь передаёт `reasoning_effort: "low"` —
модель не уходит в долгие раздумья, ответу остаётся место, и это дешевле.
Значение меняется переменной `OPENAI_REASONING_EFFORT`, пустая строка
отключает параметр совсем. Если модель его не принимает, запрос автоматически
повторяется без него. Потолок `max_tokens` поднят с 4000 до 16000.

**Первая попытка не помогла.** После выкатки карта всё равно падала. Замер на
живом сайте показал границу: при `max_tokens=4000` карта строится, при 1000 —
нет. То есть `reasoning_effort` подействовал, но приложение просило слишком
маленький бюджет — оно посылало 1000 токенов на любой запрос.

**Что доделано:** общий бюджет поднят до 3000, карте героев выделено 4000.
Потолок — не расход: платят за фактически использованные токены, а тесный
лимит приводил ровно к тому, что рассуждение съедало всё до первого слова.

**Осталось:** выкатить и убедиться на живом сайте.

### 2. «🎁 Удиви меня» повторяет книги — ИСПРАВЛЕНО В КОДЕ, ждёт выкатки

**Что происходило:** кнопка раз за разом предлагала одни и те же книги.

**Причина.** Базы книг не было вовсе — их каждый раз придумывала модель по
неизменному промпту. На один и тот же запрос она закономерно выдаёт свои
самые вероятные ответы, то есть одни и те же бестселлеры. Ничего не помнило,
что уже показывали.

Побочный риск: без списка модель могла назвать несуществующую книгу — вопреки
правилу «никогда не выдумывай» из HANDOFF.

**Что сделано.** Появился пул из **124 книг** (`src/books.js`): русская и
зарубежная классика, современная проза, фантастика, детективы, магический
реализм, азиатская литература, нон-фикшн. Книга теперь выбирается из него, а
модель пишет только загадку про конкретную, заведомо реальную книгу.

Показанное запоминается, поэтому книги не повторяются, пока пул не исчерпан —
это 42 нажатия подряд. Книги, уже стоящие на полке читателя, не предлагаются.
Когда пул кончается, память сбрасывается: лучше повтор через сто книг, чем
пустой экран.

**Проверено:** 120 книг подряд без единого повтора; из 200 подборок ни одна не
пересеклась с полкой; в браузере три нажатия дали три разные подборки.

**Пополнять список** просто — это обычный массив в `src/books.js`, строка на
книгу.

### 3. Чат не прокручивается за печатью — ИСПРАВЛЕНО В КОДЕ, ждёт выкатки

**Что происходило:** пока собеседник печатает, текст уходит вниз за край
экрана, и после ответа приходится доскроливать вручную.

**Причина.** Прокрутка делалась через `scrollIntoView` на невидимом якоре в
конце списка сообщений. Но поле ввода — `position: sticky; bottom: 0`, оно
прилипает к низу окна. `scrollIntoView` равняет якорь по нижнему краю окна —
ровно туда, где его закрывает поле ввода. Последние строки ответа оказывались
под ним.

Замер подтвердил: отставание застывало на 121 px — это в точности высота поля
ввода вместе с подписью об автосохранении.

Была и вторая причина, помельче: прокрутка запускалась плавной анимацией
каждые ~130 мс, и каждая следующая перебивала предыдущую, так и не доехав.

**Что сделано.** Прокручиваем окно к настоящему низу страницы, а не подводим
якорь. Во время печати — мгновенно, плавно только при появлении нового
сообщения.

Заодно: если читатель сам ушёл вверх перечитать, его больше не утаскивает
обратно. Намерение определяется по колесу и касанию, а не по событию `scroll` —
наша собственная прокрутка тоже его порождает, и отличить по нему человека
нельзя. Вернулся вниз — слежение возобновляется.

**Проверено замерами:** было отставание 147–165 px и 147 px в конце, стало 26 px
кратковременно и 0 в конце. Прокрутка вверх во время печати не сбивается.

## Пожелания

### B. Вход: сначала дать попробовать — СОГЛАСОВАНО, к реализации

**Проблема.** Сейчас человек упирается в экран входа с одной кнопкой Яндекса
**до того, как увидел приложение**. Ему предлагают отдать доступ к аккаунту за
нечто, чего он ещё не видел. Пять кнопок вместо одной этого не лечат.

**Решение.** Приложение открывается сразу — можно добавить книгу и поговорить
о ней. Вход предлагается позже и с понятной причиной: сохранить полку и
открывать её с другого устройства. Всегда есть «Позже».

**Порядок работ**

1. Убрать стену: приложение открывается без входа, вход — по желанию
2. Экран входа переделать: объяснение зачем, четыре кнопки, «Позже»
3. Подключить Telegram, VK ID, Google к уже работающему Яндексу
4. Предложение войти после нескольких сообщений, ненавязчиво

**Важная зависимость.** Гостевой режим сам по себе делается легко, но
**ограничить гостей по числу сообщений без базы нельзя** — счётчик негде
хранить, а клиентский обходится в две секунды. Пока базы нет, гостевой режим
означает, что `/api/claude` остаётся открытым и баланс OpenAI тратят все
подряд. Поэтому либо база идёт раньше, либо какое-то время живём с открытым
API осознанно.

**Что нужно получить владельцу** (каждое — отдельная регистрация):

| Провайдер | Что нужно | Сложность |
| --- | --- | --- |
| Яндекс ID | уже сделано | — |
| Telegram | привязать домен к боту через BotFather; токен уже есть | просто |
| VK ID | приложение на dev.vk.com | средне |
| Google | проект в Google Cloud + проверка приложения | дольше всех, проверка занимает дни |

Telegram здесь удачнее прочих: бот и токен уже есть, владелец делает канал о
приложении, а стратегическая цель из HANDOFF — Telegram Mini App. Вход через
Telegram ложится в этот путь целиком.

### C. Десктопная версия по макету

Владелец показал макет: верхняя навигация, поиск «Что хочется прочитать?»,
чипсы жанров, карточки книг с обложками, блок «Подборки для тебя», панель
AI-помощника справа, «Последние обсуждения» внизу.

Часть уже есть: изумрудная палитра, обложки книг, проценты прочитанного.

Чего нет и что потребует работы: раскладка в три колонки для широкого экрана
(приложение сейчас mobile-first, одна колонка), готовые подборки, поиск по
книгам. «Последние обсуждения» и «Сообщество» требуют базы и аккаунтов.

Отдельно — **дизайн входа для телефона**, его нужно придумать.

Владелец согласился: делаем **карту связей**, где родство — частный случай

Ниже исходное обсуждение.

---

### A1. Карта героев — не списком, а деревом

Сейчас модель возвращает плоский текст «Имя — описание», и он так же плоско
выводится.

**Что нужно для дерева:** промпт должен возвращать не описания, а **связи** —
кто кому родитель, супруг, брат. Плюс рисование самого дерева в пиксельном
стиле.

**О чём стоит подумать заранее.** «Семейное древо» подходит не всякой книге:
у Толстого и Тургенева родственные связи — костяк сюжета, а в «1984» или
«Мастере и Маргарите» героев связывают не родство, а дружба, вражда,
подчинение. Если строить строго семейное дерево, для большинства книг оно
окажется пустым.

Предложение: делать **карту связей**, где родство — частный случай наряду с
«друг», «враг», «наставник», «возлюбленные». Для семейных саг это выглядит
привычным древом, для остальных книг — тоже работает. Обсудить перед
реализацией.

## Известные незакрытые хвосты

Это не баги, а осознанно отложенное.

| | Что | Почему ждёт |
| --- | --- | --- |
| 1 | **Ассеты не нарезаны** | Три листа с артом закоммичены на Маке владельца, но не отправлены на GitHub — упирается в авторизацию git. Резчик готов: `tools/split-sheet.py` |
| 2 | **Нет базы данных** | Вход работает, но никто не записывается: сессия — подписанная кука, сервер ничего не хранит. Поэтому списка зарегистрировавшихся не существует |
| 3 | **`/api/claude` открыт всем** | Кто знает адрес сайта — тратит баланс OpenAI. Закрывается после пункта 2: сессия станет пропуском |
| 4 | **Библиотека не синхронизируется** | Книги лежат в браузере. На другом устройстве — пусто. Тоже после пункта 2 |
| 5 | **Логотип мылит** | Файл 96×77, показывается шириной 120px. Уйдёт само, когда появятся ассеты из пункта 1 |
| 6 | **`git push` не работает** | GitHub не принимает пароль с 2021 года. Нужен `gh auth login` или токен. Пока обходим загрузкой через сайт |
| 7 | **Автодеплой не подключён** | Каждый раз нужен `vercel --prod` вручную. Чинится в Vercel: Settings → Git → Connect Git Repository |
| 8 | **Оплата демонстрационная** | Про включается промокодом DEMO. Настоящие платежи — после базы и аккаунтов |

## Как описывать баг

Чем конкретнее, тем быстрее чинится:

- **Экран** — где это было (полка, чат, настройки, магазин…)
- **Что делал** — по шагам
- **Что произошло**
- **Чего ожидал**
- Телефон или компьютер, если важно

Скриншот заменяет половину описания.
