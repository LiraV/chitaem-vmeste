# HANDOFF: «Читаем вместе»
*Документ передачи разработки · 22.08.2026 · актуальные версии: веб-приложение v1.4, Telegram-бот v0.1*

---

## 1. Продукт в одном абзаце

«Читаем вместе» — ИИ-собеседник о книгах с уникальной механикой **спойлер-защиты**: пользователь указывает книгу и «закладку» (место, до которого дочитал), и собеседник обсуждает книгу строго до этого места. Ключевое правило: собеседник верит только закладке, а не словам («я уже дочитал» в чате не снимает защиту — только кнопка/команда). Дочитал → 🏁 → защита снимается, обсуждают финал. Собеседники — четыре живых персонажа с именами, биографиями и общим миром (книжный клуб). Монетизация: фримиум (2 книги бесплатно / 10 в Про за 990 ₽). Аудитория: читающие люди 16–40, которым не с кем обсудить книгу без спойлеров.

## 3. Архитектура веб-приложения (chitaem-vmeste.jsx)

Один файл, секции сверху вниз: тема/токены `T` + `THEMES` (4 палитры) → CSS в компоненте `FONTS` → i18n-словарь `I18N` (6 языков: ru/en/de/it/ja/zh) → персонажи `COMPANIONS` (промпты-биографии) и маскоты `CHARACTERS` (магазин) → `IMG` (base64-арты: 4 портрета + логотип) → ИИ-слой → хранилище → UI-компоненты → экраны → `App` (роутер).

**Стек и ограничения:** React + инлайн-стили (без CSS-фреймворков), шрифты Press Start 2P + Neucha с Google Fonts, никаких внешних ассетов (вся графика — CSS/эмодзи/base64). Mobile-first (колонка до 600px). Хранилище — `window.storage` артефактов (НЕ localStorage — он запрещён и не работает).

**Дизайн-система:** все цвета — только через токены объекта `T` (16 ключей). Тема = полная палитра в `THEMES`, применяется мутацией `applyTheme(id)` → `Object.assign(T, ...)`. Новая тема = 16 строк. Пиксельный стиль: рамки 4px `px()`, тени 4×4, свечение выбора `GLOW`, «вдавливание» кнопок через CSS `:active`.

**Навигация (state `view` в App):** `home` (титульник) → `library` / `settings` / `shop` / `ach` / `pro`; из библиотеки → `setup`, `chat`, `quotes`, `profile`. Все «назад» из разделов — в `home`, из чата/цитат — в `library`.

**Данные (2 ключа в window.storage):**
- `library-v1` — массив книг-чатов: `{id, book, progress, companionId, bookInfo, goal, messages[], quotes[], notes[], predictions[], emo[], charMap, slow, discussLang, polyLevel, summary, summarizedAt, finished, lastSeen, createdAt}`. Сообщение: `{id, role, content, meta?('divider'|'error'), hidden?}` — hidden-сообщения уходят в API, но не рендерятся.
- `settings-v1` — `{lang, theme, charId, pro, xp, spent, owned[], streak:{count,last}, minutes, tts, kids, seenIntro}`.

## 4. ИИ-слой (самое важное)

**Модель:** `claude-sonnet-4-6` через `fetch` на `/v1/messages` (ключ в артефактах подставляется автоматически; в артефактах доступна только эта модель-строка из инструкции — не менять без проверки).

**systemPrompt(chat, companion, lang, kids)** собирается из блоков, порядок важен: язык ответа (+переопределение полиглот-режимом) → книга/закладка/описание → цель → медленное чтение → детский режим → конспект-память → заметки на полях → ПРАВИЛО ЧЕСТНОСТИ (не выдумывать, признаваться в незнании книги) → СПОЙЛЕР-БЛОК (или снятие после finished) → ОБЩИЙ МИР персонажей → биография персонажа → правила «живой персонаж, не ассистент» (вкл. единственное исключение: на прямой вопрос «ты бот?» не лгать) → стиль речи с запретами на ассистентские клише.

**Экономия контекста (rolling summary):** в чат уходят только последние ~16 сообщений; при длине >24 старая часть фоново сжимается (`maybeSummarize`, шаг ~12 сообщений) в `chat.summary`, который вставляется в systemPrompt. История в storage подрезается до 280–320 сообщений.

**Вспомогательные вызовы:** `searchBookInfo` (веб-поиск описания книги, инструмент `web_search_20250305`), `recommendNext` (персональные рекомендации: контекст = полка + summary + цитаты; настроения any/sim/new/light/deep/short), `blindRecs` («свидания вслепую»), `buildCharMap` (карта героев без спойлеров).

**Критический паттерн парсинга:** ответы ИИ парсим НЕ через JSON, а через построчный формат с латинскими метками (`TEASER:`/`BOOK:`, `TITLE:`/`AUTHOR:`/`WHY:`) + 2 попытки + текстовый фолбэк. JSON от моделей ломается; этот формат — нет. Сохранять паттерн для новых функций.

**Скрытые команды:** викторина, дебаты, письмо, рецензия, вскрытие предсказаний, «вернулся после паузы» (>6 ч), реакция на сдвиг закладки — всё реализовано hidden-сообщениями от имени пользователя.

## 6. Известные ограничения и техдолг

1. **Оплата демонстрационная** — промокод DEMO вместо кассы; настоящие платежи только на этапе TG/сайта.
2. **Публичная ссылка требует логина в Claude** у открывшего (ограничение ИИ-артефактов).
3. **Нет тестов вообще**; ручное тестирование фрагментарное. Самый недотестированный пласт — связки функций (полиглот+викторина, детский+дебаты и т.п.).
4. **Модель одна и средняя** — «мозг» слабее флагманских; лечится качеством промптов, при переносе на свой API можно поднять модель.
5. TTS/голосовой ввод зависят от браузера (iOS Safari капризен), кириллица в Press Start 2P на грани читаемости при мелких кеглях (<9px не использовать).
6. Маскоты на полке — ещё CSS+эмодзи; в ассет-паке пользователя есть арты всех семи (плюс бейджи, стикеры, фоны) — не вшиты из-за веса, ждут хостинга.
7. Файл монолитный: правки делаются точечными заменами по якорям; перед серьёзными изменениями — проверка синтаксиса esbuild.
8. Невозможно в артефакте: push-уведомления, реальный мультиплеер (совместное чтение), фоновые задачи.

## 7. Telegram-ветка (следующий большой этап)

**Есть (v0.1):** aiogram 3, SQLite, ядро — спойлер-защита (верит только /mark), честность, полка /books, 3 персонажа, /mark, /finish, память по книге. Локальный запуск по инструкции.
**Дальше по порядку:** (1) пользователь получает токен BotFather + ключ API (console/platform.claude.com, ~$5) и запускает локально; (2) хостинг 24/7 (~$4–6/мес); (3) персоны из v1.4 перенести в bot.py (сейчас там старые «роли»); (4) платежи Telegram Stars для Про; (5) стратегическая цель — **Telegram Mini App**: наш JSX почти целиком переносится внутрь бота, там появляются настоящие ссылки, логин из коробки, уведомления и вся графика ассет-пака с хостингом.

## 8. Ключевые продуктовые решения (не ломать!)

- Закладка — единственный источник истины для спойлеров; слова пользователя её не двигают.
- Персонажи никогда не говорят ассистентским канцеляритом; на прямой вопрос «ты бот?» не лгут (доверие + требования законов о раскрытии ИИ).
- ИИ-ответы парсим построчными метками, не JSON.
- Ошибки — всегда человеческим языком на языке интерфейса (`t("errMsg")`), с автоповтором ×3 внутри.
- Цвета — только через токены T; хардкод цвета = баг.
- Владелец продукта — новичок в разработке: объяснять изменения по-человечески, техжаргон переводить.
